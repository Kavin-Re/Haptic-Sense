## 3. THE BLOCKER AND THE FIX — 10 minutes, no parts

Full reasoning and arithmetic:
`docs/evidence/phase5/PHASE5_VIN_BROWNOUT_20260901.md`.

| node | measured | expected |
|---|---|---|
| CN8 pin 4, system 3V3 rail | 3.32 V | ✓ |
| DRV2605L breakout VCC | 3.31 V | ✓ (10 mV drop) |
| **7SEMI VL53L1X VIN** | **2.04 V** | should be ~3.31 V |

DS12385 Rev 8: **AVDD min 2.6 V.** 2.04 V is **560 mV below the minimum**.

**Power OFF, DMM on continuity:**
- [ ] **3V3 rail → 7SEMI VIN pad: must be < 1 Ω.**
- [ ] **CHECK THE BREADBOARD POWER-RAIL SPLIT FIRST.** Most breadboards break
      the `+` and `−` rails mid-strip. DRV2605L on one half and the 7SEMI on
      the other leaves the 7SEMI with no supply — which is exactly what 2.04 V
      through its own pull-ups looks like. **Top candidate.** Bridge the halves.
- [ ] **7SEMI GND pad → CN8 pin 7: < 1 Ω.** A missing return does the same.
- [ ] Reflow both joints, reseat both jumper ends.
- [ ] Power up: **VIN at the 7SEMI pin must read ≥ 3.2 V.**

**Do not flash, code, or capture until VIN ≥ 3.2 V.** Every reading taken below
2.6 V describes a brownout, not the design.

## 4. THEN — build, flash, and what PASS looks like

```bash
timeout 60 picocom -q -b 115200 /dev/ttyACM0 | tee /tmp/vinfix.log
grep -E '^\[(I2C|NAK|RNG|PRT|RTY|DRV)\]' /tmp/vinfix.log | head -24
```

```
[RNG] init=0 step=99 id=0xeacc boot=1 calls=~100 xerr=0 dm=1 tb=15
[RNG] osc=<nonzero> imp=<nonzero> imprb=<same> mstart=0x40 cfg=91 cfgfail=0x0
[RTY] wr=0 wmax=0 wref=0  rd=0 rmax=0 rref=0     <-- ALL ZERO = supply fixed
[I2C] ... err=0 tmo=0 recov=0     [NAK] nacks=0
[RNG] frames=<climbing ~40-50/s> last=<mm> min=.. max=.. dxfer=0
```

**`[RTY]` all zero is the proof.** Those counters exist to ride out a fault; on
healthy hardware they must read zero, and they are now a permanent
supply-health regression detector. Then wave a hand at it — `last=` tracks
distance in mm. **Photograph that terminal: first real sensor reading in the
project.**

`[RNG] step=` names the first gate that did not hold: 1 boot, 2 id, 3 config,
4 distance mode, 5 timing budget, 6 inter-measurement, 7 StartRanging.
`cfg=` short of 91 with `cfgfail=0x00XX` names the register that refused.

### 4.1 If `[RTY]` is still non-zero with VIN ≥ 3.2 V
Local decoupling. DS12385's layout note: *"Place the capacitors on the external
supply AVDD as close as possible to the AVDDVCSEL and AVSSVCSEL."* The VCSEL
fires in short high-current pulses; **0.1 µF + 10 µF ceramic soldered at the
7SEMI's VIN/GND pins** is the right part. A 100 µF electrolytic is too slow and
too high-ESR to help the VCSEL, though it is still owed on the rail (T3 step 5).

### 4.2 The pad fix, for the record
ST's `VL51L1X_DEFAULT_CONFIGURATION[]` (`VL53L1X_api.c:62-63`), verbatim:
```
0x00, /* 0x2e : bit 0 if I2C pulled up at 1.8V, else set bit 0 to 1 (pull up at AVDD) */
0x00, /* 0x2f : bit 0 if GPIO pulled up at 1.8V, else set bit 0 to 1 (pull up at AVDD) */
```
This board's pull-ups measure 2 × 9.9 kΩ **to VIN**, and VIN is the 3.32 V rail.
Per ST's own comment bit 0 must be **1** in both; the ULD writes 0. Our config
loop ORs 0x01 into both. **Not the root cause — but wrong for this board
regardless, and leaving it would be a latent defect.**
