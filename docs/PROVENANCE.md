# Provenance of third-party and replaced files

Record of where non-original code in this repository came from, and of files
that were removed or replaced because their stated origin was wrong.

## Replaced 2026-09-25

| Removed | Replaced by | Why |
|---|---|---|
| `firmware/Appli/Core/Inc/serial_protocol.h` | `firmware/Appli/Core/Inc/boot_log.h` | Carried a "Copyright (c) 2025 STMicroelectronics" header, but a 2026-09-24 comparison found it in no ST or TRON Forum upstream this project draws on (`tron-forum/mtk3_bsp2`, `tron-forum/mtkernel_3`, `STMicroelectronics/STM32N6-GettingStarted-ObjectDetection`). It arrived via the bring-up reference repository `supungamlath/STM32N6_Survivor_Detection`, which has no license. With no verifiable license grant, it was not redistributed. |
| `firmware/Appli/Core/Src/mtkernel_bsp.c` | `firmware/Appli/Core/Src/hal_timebase_mtk.c` | Same situation as above. |

Both files were load-bearing (verified from the 2026-09-19 build's `.map`):
`main.c` used `serial_protocol.h` for its boot log, and the linker resolved
`HAL_GetTick` / `HAL_Delay` / `HAL_InitTick` from `mtkernel_bsp.o`. The
replacements were written for this project from the call sites and the
STM32 HAL / µT-Kernel 3.0 interfaces, implement only what the build uses,
and keep the boot-log output format and the time-base behaviour unchanged.
`mtkernel_bsp.c`'s `TIM4_Config()` / `TIM4_Get_Value()` had no callers and
were not carried over.

Verified 2026-09-25: full Debug build compiles and links with
arm-none-eabi-gcc 13.3.1; the three HAL time-base symbols now resolve from
`hal_timebase_mtk.o`. Not yet re-flashed on hardware (the unit shipped for
judging on 2026-09-21 with the pre-swap binary).
